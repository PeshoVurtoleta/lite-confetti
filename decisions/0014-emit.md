# 0014 -- spawn emitter shapes (`emit`, the first EMISSION-GEOMETRY feature)

- **Status:** accepted (implemented in v1.13.0)
- **Date:** 2026-08-06
- **Session:** F12, the release after F11 (v1.12.0 lifeColors). Where 0005-0009 extended the PHYSICS,
  0010/0013 built the RENDER path (trails, color-over-life), 0011 added a DIRECTED force (vortex), and
  0012 added the first BEHAVIOUR feature (settle), this opens a NEW axis: EMISSION GEOMETRY -- it
  changes WHERE a particle is BORN, not how it moves, ends, or is drawn.

## Context

Until now every burst spawned from the single point `(x, y)`. Real confetti effects want an origin
with shape: rain / snow falling from a horizontal LINE across the top, a firework shell expanding from
a RING, a burst filling a BOX area. This chapter adds **`emit`**: an opt-in emitter that distributes
the spawn ORIGIN over a shape, sized by a single `emitSize` scalar.

The interesting engineering is not a force but the RNG contract: `emit` is the FIRST feature to add a
CONDITIONAL spawn-time rng draw. Every prior feature is either zero-rng (forces, trails, color) or
rides the fixed base spawn sequence. A new spawn-time draw threatens the whole determinism guarantee
unless it is placed so that OFF is a no-op on the sequence.

## Decisions

1. **Single `emitSize` scalar, chosen over an `emit` object.** Confirmed via AskUserQuestion. One
   fail-closed scalar sizes every shape -- line half-length, ring radius, box square half-extent --
   matching the house style (scalar knobs, coerced fail-closed, off = byte-identical). An `emit`
   object (`{ shape, length, angle | radius | width, height }`) would be more expressive (angled
   lines, rectangular boxes) but introduces an object-shaped option unlike every other knob and a
   wider coercion surface. Angled lines and rectangular boxes are deferred (see NOT done).

2. **Ring = radial shell, chosen over position-only.** Confirmed via AskUserQuestion. For `emit:'ring'`
   ONLY, each piece's velocity points radially OUTWARD from the ring centre (`speed` = shell expansion
   rate, `spread` = angular fuzz around the outward radial angle) -- the firework-shell money shot,
   the reason a ring emitter is worth having. This is a deliberate, ring-ONLY coupling of emission
   geometry to velocity direction; `line` and `box` leave velocity to `angle`/`spread` and move only
   the origin. The ring reuses the already-drawn spread jitter (`j = a - angle`) around the outward
   angle, so it adds NO extra rng draw beyond the one for the point on the circle.

3. **The conditional spawn-rng contract -- the load-bearing property.** The emitter branch sits in the
   burst/spray spawn loop, AFTER the speed draw and BEFORE the `spawn()` call. `emitId === EMIT_OFF`
   (the default) inserts NOTHING -- the loop draws the identical `a` (angle) then `s` (speed) then
   calls the point `spawn()` -- so the seeded stream, and therefore EVERY committed position
   fingerprint, is byte-identical to a point burst (`1569828004` and all prior physics/trail/color
   hashes preserved). Per-shape draw counts differ: `line`/`ring` draw 1 rng value (the parametric
   position), `box` draws 2 (independent x/y). Because the counts differ, each shape earns its OWN
   committed hash (`line 2558715937`, `ring 2441425203`, `box 2748626140`), all distinct from the
   point spawn and each other; within a shape the count is fixed, so it replays identically.
   - **No probe was needed.** Unlike trails / lifeColors (which draw in world space or move only
     `fillStyle`, invisible to the position `hash`, so they needed `strokeHash` / `colorHash`), `emit`
     MOVES the spawn origin, and the mock canvas already folds `translate(x, y)` into the position
     `hash`. So the existing fingerprint observes the emitter directly.

4. **`emit` resolves once to a small int id.** A module `EMIT_ID` (`Map<string,int>`) plus
   `EMIT_OFF/LINE/RING/BOX` consts turn `emit` into an int per `burst()`/`spray()` (`emitId`/`emitR`
   locals), so the spawn loop branches on an int compare, never a string. `spawn()`'s signature is
   UNCHANGED -- the emitter computes the origin (and, for ring, the velocity) in the caller and passes
   them in place of `cx, cy, cos(a)*s, sin(a)*s`. All emitter math is a few multiplies on stack
   locals -- zero allocation.

5. **Fail closed.** An unknown shape name, a non-string `emit`, or a non-positive / non-finite
   `emitSize` collapses to `EMIT_OFF` -- a point spawn (`emitId = EMIT_ID.get(emit) ?? EMIT_OFF`;
   `emitR = nonneg(emitSize, 0)`; `if (emitR <= 0) emitId = EMIT_OFF`). The origin is an offset of the
   finite burst centre, so no non-finite draw position can result.

6. **No reduced-motion effect.** The static accessible fan (`renderStaticBurst`) lays pieces out with
   no rng origin, so `emit` is inert there -- consistent with every motion feature.

7. **Hot path untouched.** `emit` lives entirely at spawn; `update()` and the render loop are
   unchanged. It is the first feature whose whole cost is at burst time, not per frame.

## Consequences / proof

- Unit suite 149 -> 157. New `describe('emit / emitter shapes')` asserts: OPT-IN / fail-closed (off /
  unknown / non-string / `emitSize` 0 / negative / NaN / non-numeric all reproduce `COMMITTED_HASH`);
  prior gates still hold with emit off (`FLOOR_HASH`, `BOX_HASH`); a committed fingerprint per shape,
  all distinct + deterministic; NON-VACUOUS line geometry (the X band widens by ~2*emitSize over the
  point spawn); NON-VACUOUS ring coupling (a radial shell's X and Y spreads are near-equal at
  gravity 0, vs an asymmetric point cone); `assertFinite` under emit + gravity + bounce in a box;
  spray honours emit (deterministic, shifts the stream); reduced-motion inert.
- Torture: T5 threads a random `emit` shape + `emitSize` (half off) through the differential fuzz (two
  same-seed instances stay bit-identical -- the emitter draws are deterministic). T6 adds a continuous
  ring-emitter SPRAY lane so the emitter branch runs INSIDE the measured window (the other lanes burst
  once, before it) -- still ~0 B/frame at spawn. T1 adds emit poison (unknown shape / non-string /
  size NaN / 0 / negative / huge / Infinity / absent / valid-in-box) under the finite-position
  detector -- all fail closed to a point spawn, nothing crashes, no NaN reaches a draw.
- Full gate matrix green: 157 unit; torture ok / BREAK exit 1 / CONTROL=alloc exit 1 / SEED ok; ASCII
  clean; npm pack 1.13.0.
- Cost: three module consts + one `Map`; two locals per `burst()`/`spray()`; one int-compare branch
  per spawned particle (the default path) plus, when armed, 1-2 rng draws and a few multiplies.

## Explicitly NOT done (flagged for a future chapter, if ever)

- **Angled lines / rectangular boxes** -- the single-`emitSize` scalar gives a horizontal line and a
  square box; orientation + independent width/height would need the `emit` object rejected in
  decision 1.
- **Arc / spline / polygon emitters** -- line/ring/box are the three canonical origins; richer paths
  are a separate feature.
- **Per-emitter velocity modes for line/box** (e.g. a line that also fires radially) -- the
  radial-shell coupling is intentionally ring-ONLY; line/box stay position-only.
- **An emitter on the reduced-motion static path** -- the static fan is a fixed accessible layout;
  emission geometry is a motion-time concern.
- **Multiple simultaneous emitters in one burst** -- one `emit` per burst/spray; layering is achieved
  by firing multiple bursts.
- Any change to the default look, existing presets, the physics integrator, the trail/color overlays,
  or any committed position/trail/color fingerprint when emit is off.
