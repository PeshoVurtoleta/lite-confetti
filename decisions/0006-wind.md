# 0006 -- wind (lateral drift)

- **Status:** accepted (implemented in v1.5.0)
- **Date:** 2026-08-01
- **Session:** F4, the feature release after F3 (v1.4.0 multi-shape mixing). The ledger's
  last deferred *feature* shipped in 0005, so this opens a new direction rather than
  paying debt: completing the force model.

## Context

Confetti physics is **down-only**. The one force is a scalar `gravity` on the Y axis
(`update()`: `pool.vy[i] += pool.grav[i] * dtSec`). The single lateral motion knob,
`sway` (0003, v1.3.0), *oscillates* -- `x += sin(tilt) * sway * SWAY_PX * dt` -- so it
nets to zero drift, which is exactly right for paper flutter but cannot make a whole burst
*travel* sideways. There was no way to express a breeze, a slanted fall, or a side-cannon
plume that keeps going.

`wind` adds the missing lateral **acceleration** -- the exact X-axis mirror of `gravity`.
`gravity` (down) + `wind` (across) then read as a single 2D force vector. It is the
tightest possible fit to the proven fingerprint-safe-knob discipline this package already
uses for `sway`, `flutter`, and `shapes`.

## Decisions

1. **`wind` is a lateral acceleration in px/sec^2 -- gravity's units, not a 0..1
   amplitude.** Sharing units with `gravity` is the whole point: a caller reasons about one
   force vector (down + across), and `{ gravity, wind }` composes arithmetically. A 0..1
   "amplitude" (the `sway` shape) was rejected -- it would have hidden the physical
   relationship and needed an arbitrary internal scale constant.

2. **Guarded off by default, following `sway` -- not unguarded like `gravity`.** In
   `update()`, immediately after the gravity line:
   `if (pool.wind[i] !== 0) pool.vx[i] += pool.wind[i] * dtSec;`. The guard makes
   hash-neutrality *structural*: the branch cannot fire at the default, so a non-`wind`
   burst is byte-identical and the committed default fingerprint `1569828004` is preserved.
   `gravity` is unguarded only because its default (600) is non-zero and always meaningful;
   `wind`'s default is 0, so it follows the `sway` precedent (which guards for the same
   reason, plus to skip its `Math.sin`). Placed **before** the two `*= drag` lines, so wind
   -- like gravity -- is damped toward a terminal lateral velocity rather than accelerating
   without bound. Symmetric physics.

3. **A per-particle `wind` pool column, mirroring `grav`.** Required, not optional:
   different bursts/sprays coexist in one pool over time, so a windy burst and a still burst
   must carry independent wind -- exactly why `grav`/`drag`/`flut`/`sway` are already
   per-particle. Cost is 4 bytes/particle, matching the existing force columns; there is no
   way to fold it into an existing column without breaking mixed-burst correctness.

4. **Coerce with `num`, not `nonneg` -- wind is signed.** Leftward drift (negative wind) is
   a first-class use, so `wind = num(wind, 0)`: a NaN/Infinity/string fails closed to 0 (no
   wind, never a NaN position), but negatives pass through. One-shot coercion per call, like
   `gravity`, never on the hot loop. This is the coerce-don't-throw stance of 0004 s1: a
   call-time typo must not crash a running animation.

5. **No effect under reduced motion -- intentionally.** `renderStaticBurst` places a
   settled static scatter with no integration or velocity, so wind (a motion force) has
   nothing to act on. Unlike `shapes` (geometry, which the static path had to honour, 0005
   d5), wind needs *no* static-path change; it is simply inert there, like `sway`/`flutter`.

6. **This is a minor (1.4.0 -> 1.5.0).** `wind?: number` is a new *public* option
   (`Confetti.d.ts`), so semver minor -- matching the `flutter`/`sway`, `registerShape`, and
   `shapes` feature precedents. Existing presets are left unchanged (conservative; the
   feature is opt-in and the demo showcases it rather than altering a shipped look).

## Why wind is hash-neutral by default AND deterministic when on

Two separate properties, both required:

- **Default preserved.** The guard (decision 2) means a `wind`-absent burst executes the
  identical instruction stream as pre-1.5.0. The committed default fingerprint
  `1569828004` is byte-for-byte unchanged -- verified by the unit gate running
  omit/`0`/`NaN`/`Infinity`/string all against that constant.
- **Windy burst deterministic.** Unlike the `shapes` mix (0005), wind draws **no** rng --
  it is pure integration. So a windy burst does not shift the rng stream at all; it merely
  adds a per-frame lateral term to positions that were already determined by the seed. It
  therefore replays identically under a fixed seed, with its own committed fingerprint
  `2385225781` (asserted `!==` the default hash, since a non-zero wind must move positions).

## How the tests prove it -- measuring drift *direction*, not just determinism

A position fingerprint proves the windy stream is deterministic but says nothing about
*which way* it leans (any lateral shift changes the hash equally). So, as the analog of
0005's "count dispatches, not positions", this chapter measures **net displacement**: the
mock ctx (`test/_env.mjs`) gains a `sumX` accumulator -- the net signed sum of integer
draw-X -- kept entirely out of the `hash` mix (so every committed fingerprint is
byte-identical whether or not it is read). A test then runs the *same seed* at `wind: +K`,
`0`, and `-K` and asserts `sumX(+K) > sumX(0) > sumX(-K)`: the sign proof a bare hash
cannot give.

- **Unit** (`wind (lateral drift)` describe): omit/`0`/`NaN`/`Infinity`/string all
  reproduce `1569828004` (opt-in + fail-closed in one); a canonical `wind: 300` burst
  reproduces `2385225781` and is `!==` the default; the `sumX` directionality ordering;
  positions stay finite under a strong negative wind (assertFinite); spray honours wind;
  reduced-motion is wind-inert (same static hash with and without wind).
- **Torture T5**: signed `wind` is threaded into the differential fuzz op-stream (burst and
  spray), so two same-seed instances running the identical windy corpus stay bit-identical
  frame for frame across 3000 ops.
- **Torture T6 lane 5**: the full multi-shape pool now also carries `wind: 300`, arming the
  guarded lateral-accel FMA for every particle every frame; it still integrates at ~0
  B/frame (the guard/FMA de-opts nothing).
- **Torture T1**: `wind: NaN` and `wind: -Infinity` join the poison barrage under the
  finite-position detector -- coercion to 0 holds, no NaN reaches a drawn position.

## Explicitly NOT done

- A separate gravity-vector API (`gx`/`gy` aliases) -- `gravity` (down) + `wind` (across)
  already express the 2D force; aliases would be redundant public surface.
- Turbulence / a noise field / gusting (time-varying wind) -- wind is a constant per-burst
  acceleration, deterministic. A gust field would need its own rng stream (and would break
  the "windy burst draws no rng" property above), so it is a separate chapter if ever.
- Per-shape or per-particle wind -- wind is burst-wide, like gravity.
- No change to the default straight-fall path, existing presets, the default look, or the
  committed default fingerprint `1569828004`.
